# Olais Eval — Candidate Instructions

## Welcome

You've been invited to participate in a practical engineering evaluation. This is NOT a LeetCode test. This is NOT a timed coding interview.

This is a real-world engineering challenge. We evaluate how you think, build, deploy, and use tools — including AI.

---

## What You Need To Do

### 1. Choose Your Problem

You'll receive 2 problem statements after completing a short skill assessment. Pick the one that suits you best. You can submit both if you want.

### 2. Build It

Use whatever tools you want:
- **Any AI** — Claude, ChatGPT, Cursor, Copilot, Windsurf, whatever you're comfortable with
- **Any stack** — Next.js, Python, Go, Rust, whatever solves the problem
- **Any approach** — as long as it works and you understand it

### 3. Store Everything in Git

Create a **public GitHub/GitLab repository** for your solution. Your repo should include:

```
your-solution/
├── src/                    # Your code
├── prompts/                # ← IMPORTANT: Save ALL prompts you used
│   ├── prompt-01-initial-setup.md
│   ├── prompt-02-feature-x.md
│   └── prompt-03-debugging.md
├── README.md               # What you built, how to run it
└── ARCHITECTURE.md         # Your thought process & decisions
```

The `prompts/` folder is critical. Save every prompt you sent to AI tools — the ones that worked AND the ones that didn't. This is part of your evaluation. We want to see how you collaborate with AI.

### 4. Deploy It Anywhere (Free)

Deploy your solution on any free platform:
- **Vercel** (easiest for Next.js/前端)
- **Railway** (full-stack, free tier)
- **Render** (web services, free tier)
- **Netlify** (static sites, serverless)
- **Fly.io** (full-stack, free allowance)
- **Cloudflare Pages** (static, workers)
- **GitHub Pages** (static)
- **PythonAnywhere** (Python backends)
- Your own server if you have one

Pick whichever you're comfortable with. We just need a live URL.

### 5. Submit

On the portal, submit:
- Your **GitHub/GitLab repo URL**
- Your **live deployment URL**
- A short **architecture explanation**
- Your **AI usage declaration** — what tools, what prompts worked, what you wrote manually

---

## Evaluation Criteria

We're looking at:

| What matters | Why |
|-------------|-----|
| **Execution quality** | Does it work? Is it solid? |
| **Architecture** | Did you think about structure? |
| **AI usage maturity** | Did you use AI effectively or blindly? |
| **Deployment** | Did you get it live? |
| **Code organization** | Is it readable and maintainable? |
| **Communication** | Can you explain your decisions? |

We do NOT care about:
- Memorizing syntax
- Algorithm trivia
- Writing code from scratch without AI
- How fast you type

---

## Timeline

- You have **several days** from when you receive your problem
- Timer tracks elapsed time from when you first view the problem
- All submissions due by the campaign deadline
- Results announced after evaluation

---

## Pro Tips

- **Use AI aggressively.** That's the point. But understand what it produces.
- **Save your prompts.** We literally want to see them. It's part of the score.
- **Deploy early.** A partially working deployed app > perfect local code.
- **Write your ARCHITECTURE.md as you go.** Don't leave it for the end.
- **If stuck, document why.** Shows debugging maturity.

Good luck. Build something you're proud of.
